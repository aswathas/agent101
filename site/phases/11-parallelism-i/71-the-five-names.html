LEARN · PHASE 11 · LESSON 71

The Five Names

You can name the mechanism a task needs before you run it — and say what each

Type
Learn
Prerequisites
Phase 02 Lesson 13 (Branches Are Movable Labels); Phase 04 Lesson 31 (The Agentic Loop); Phase 06 Lesson 45 (Subagent Markdown Format)
Time
~30 minutes

Learning Objectives

  • Name the five mechanisms and, for each, say what it isolates
  • Choose a mechanism from the isolation a task needs, not from a feature name
  • Explain why "many agents" is the wrong question to start from
  • Say which of the five a task does not need, in one sentence

The Problem

A change touched twenty files. The instinct was "spawn agents." Five subagents went out, all editing the same checkout. Two of them wrote the same file. The work that survived was fine. The work that didn't was a merge with no branch to merge.

Recovering it cost a restart and a manual re-apply. Nothing was wrong with the subagents. The wrong name was chosen for the job.

Four words were in play — subagent, team, worktree, workflow — plus a fifth that isn't a mechanism at all. They read like synonyms when you are holding a task and deciding. They are not synonyms. Each one is a different answer to "what must not collide?"

The Concept

Claude Code ships several things that look like "run work in parallel." Five names cover almost everything a learner reaches for. They are not five settings on one dial. They are five different axes of isolation.

NameWhat it actually isWhat it isolatesWho holds the plan
SubagentA worker inside your one sessionIts context windowClaude, turn by turn
Teammate (an agent team)Peer sessions a lead runsWho owns which taskThe lead, over a shared task list
WorktreeA second checkout of the repoThe files on diskYou, or the harness for you
WorkflowA script that runs many subagentsThe plan itselfThe script
/batchA packaged fan-outBoth: it uses subagents and worktreesThe skill's plan

Read the middle column, not the name. That column is the whole lesson.

  • A subagent keeps its mess out of your window. It does not keep it out of your files. Two subagents in one session share one working directory.
  • A teammate is a full session that can message its peers and claim work. It gives you coordination, not file isolation — teams do not isolate teammates in worktrees, so you partition the files yourself.
  • A worktree is the only one of the five that isolates files. It is not a worker. It is a copy of the repository where a worker can safely run.
  • A workflow moves the loop out of Claude's turn-by-turn judgment and into a script. What it isolates is the plan, so a 500-file job doesn't have to fit in one conversation.
  • /batch is not a sixth mechanism. It is a skill: it decomposes a change into units and runs one isolated subagent per unit.

Two more names exist, and this lesson is honest about leaving them out. Agent view (background sessions you dispatch and watch) is Phase 12 — it is mostly how you monitor work, and it has nothing to say about what collides. Projects runs in the cloud and is out of scope for this course, which is local-first. Neither is one of the five you pick between at the keyboard.

The reframe: the five names do not differ by how many agents they run —

they differ by what they isolate, and choosing one is choosing which collision

you are trying to prevent.

Claude Code ships weekly and these names move. The comparison this lesson is built on lives at Run agents in parallel; check it before trusting a row. Workflows are also off by default on some plans.

Build It

1. Inventory what your install actually has

claude --version
env | grep CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS || echo "agent teams: off"

Open a session and run /agents, then /batch with no argument. One lists your subagent files; the other tells you what it needs before it runs.

✅ You pass when you can say which of the five names are available in your build right now, and which need turning on.

2. Take three real tasks and assign each an axis

Write them down before choosing a name. For each task, answer one question: what must not collide?

Task: "read every file under src/ and report the two that log a secret"
Collision to prevent: my context window filling with 400 file reads
Axis: context
Name: subagent

Task: "rewrite the import style in 30 files"
Collision to prevent: two editors writing one file at once
Axis: files
Name: worktrees

Task: "audit the whole codebase for the same bug, cross-checking findings"
Collision to prevent: a job too big for one turn, needing verification
Axis: the plan
Name: workflow

✅ You pass when each task has an axis written next to it, and the axis was decided before the name.

3. Try the wrong axis on purpose

Take the import-rewrite task and do it as five subagents with no worktrees. Watch them share one directory. Then do it again with isolation: worktree (Phase 11, Lesson 74).

✅ You pass when you can point at the run that collided and name the column in the table above that would have prevented it.

Use It

Reach forWhen the thing that must not collide is…
A subagentYour context window. Big searches, logs, file dumps you won't quote again.
A teammateWho owns which task, and the workers need to talk to each other.
A worktreeThe files. Any time two writers touch the same checkout.
A workflowThe plan. Dozens to hundreds of agents, or findings that must be cross-checked.
/batchA large mechanical change you'd otherwise script by hand. It is subagents plus worktrees, packaged.
NothingThe task is one file and one decision.
Agent viewYou want to dispatch and watch several independent sessions. Phase 12.

Exercises

  1. Write the five names in a column. Next to each, write the one thing it isolates, in three words or fewer. Do it from memory first, then check the table. ✅ You pass when all five rows name a different thing, and none of them says "files" except the worktree row.
  1. Take a task from this week that you ran (or could have run) with an agent. Name the mechanism you used and the axis it isolated. If you used "none," name the axis that didn't need isolating. ✅ You pass when your answer names the collision you were or weren't preventing, not the feature you clicked.
  1. A colleague says "let's spin up a team to land this 12-file refactor." Write two sentences back: what team gives you, and what it doesn't. ✅ You pass when your reply says teams share files, so the 12 files need partitioning or worktrees — not just coordination.

Key Terms

TermWhat people sayWhat it actually means
subagent"a parallel agent"A worker inside one session. Isolates context, not files.
teammate"another agent"A full session in an agent team, coordinated through a shared task list and a mailbox. Not worktree-isolated.
worktree"a branch"A second working directory with its own checkout. The only one of the five that isolates files.
workflow"a big prompt"A script that holds the plan and runs many subagents. Isolates the plan from your conversation.
/batch"run it everywhere"A skill that splits one change into units and runs one worktree-isolated subagent per unit. Subagents plus worktrees, packaged.
axis of isolation"how parallel it is"The single thing a mechanism keeps from colliding. The word that actually decides your choice.
agent view"the agent dashboard"A screen for dispatching and watching background sessions. A monitoring surface, not an isolation axis. Phase 12.

What this lesson skipped

Worktrees in depth. Branch names, base refs, .worktreeinclude, cleanup, and per-agent isolation are Lessons 74 and 75, and all of Phase 16.

Agent teams' mechanics. The mailbox, the task list, and the documented limits are Lesson 73.

Workflows. The script API, parallel() vs pipeline(), and the completion-order trap are all of Phase 12.

Projects and cloud sessions. Out of scope for a local-first course. If you move work to the cloud, read Claude Code in the cloud.

Cost. Every name here multiplies token usage. Phase 03 Lesson 11 owns the budget side; this lesson is about collisions, not spend.

Check yourself

4 questions. Answer before you reveal — recognising the right option is not the same as being able to produce it.

  1. Your task is to read every file under src/ and report the two that log a secret. You don't want 400 file reads in your own conversation. Which of the five names fits, and why?

    1. A worktree, because the reads must not touch the real checkout
    2. A subagent, because the axis to isolate is the context window
    3. /batch, because the work spans many files
    4. A teammate, because the reads need to be shared with peers
    Show answer

    B. A subagent, because the axis to isolate is the context window

    The collision to prevent is your window filling with reads you won't quote again — that is context isolation, which is exactly what a subagent provides. A worktree isolates files, and reading doesn't write files, so it buys nothing. /batch is for mechanical changes across many files, not a read-and-report. A teammate adds coordination and still shares your files, which is the opposite of the problem here.

  2. You spawn five subagents to rewrite import style across 30 files. Two of them edit the same file and one overwrites the other. What was the missing mechanism?

    1. A bigger model on each subagent, so they plan before editing
    2. A shared task list, so the subagents claim files in order
    3. A worktree per subagent, because subagents isolate context and not files
    4. A workflow, because workflows cross-check each other's edits
    Show answer

    C. A worktree per subagent, because subagents isolate context and not files

    Subagents share your working directory, so parallel writers collide no matter how well they reason. Each editor needs its own checkout — isolation: worktree. A shared task list coordinates who does what but not which directory they write to, so the overwrite can still happen. A workflow orchestrates the plan; it doesn't give each agent a separate filesystem by itself.

  3. Three reviewers should each take a different lens on the same pull request — security, performance, and test coverage — and challenge each other's findings before you see a merged verdict. Which name is built for this?

    1. An agent team, because teammates message each other and coordinate over a shared task list
    2. A single subagent with three lenses in its body
    3. A worktree per reviewer, so each sees a clean checkout
    4. /batch, because it splits work into 5 to 30 units
    Show answer

    A. An agent team, because teammates message each other and coordinate over a shared task list

    The defining feature here is reviewers talking to each other and coordinating — that is what agent teams add over subagents. One subagent with three lenses is still one voice and can't argue with itself. Worktrees isolate files, and reviewers aren't writing files, so three clean checkouts add cost and no coordination. /batch fans out isolated edits; it doesn't create a conversation between reviewers.

  4. /batch is often called a sixth mechanism, alongside the other four. What is it actually?

    1. A separate scheduler that runs sessions on a timer
    2. A packaged skill that uses subagents and worktrees together
    3. The command-line form of an agent team
    4. A monitor that watches background sessions for you
    Show answer

    B. A packaged skill that uses subagents and worktrees together

    /batch is a skill: it decomposes one large change into units and runs one worktree-isolated subagent per unit — so it is subagents plus worktrees with a name, not a new kind of agent. A timer scheduler is routines. An agent team is a lead plus message-passing peers. The screen that watches background sessions is agent view.
