LEARN · PHASE 13 · LESSON 86

What Loads, What Costs

After this lesson you can open `/context` and point at the blocks that loaded

Type
Learn
Prerequisites
Lesson 32 (What Loads Into the Window), Lesson 44 (Author a Skill), Lesson 65 (CLAUDE.md)
Time
~30 minutes

Learning Objectives

  • Run /context and separate the auto-loaded blocks from the on-demand ones
  • Name what loads before your first message: system prompt, memory, project instructions, the rule listing, skill descriptions, and MCP tool names
  • Say which startup blocks you can shrink and which you cannot touch
  • Move one always-loaded block to on-demand and watch the startup number change
  • Predict, before a task starts, which file reads will dominate the rest of it

The Problem

One more checklist. One more skill. One more MCP server. Each felt free when you added it.

Six weeks later every session opens slow, and Claude starts ignoring a rule that sits in the middle of CLAUDE.md. Nothing errored. Nothing is broken. Your window filled up before you typed, and you never saw the bill.

That is the whole trap: the expensive content is the content you stopped noticing. You watch the tokens you spend on a task. You do not watch the tokens you spend before the task, every time, whether you need them or not.

The Concept

The context window fills in two waves.

The first wave loads before your first message. You do not ask for it, and most of it you never see.

The second wave loads only when something needs it — a file read, a rule that matches, a skill you invoke.

What loads at startup

BlockWhat it isCan you shrink it?
System promptCore instructions and tool definitions. Not yours.No — it is fixed and you never see it.
Auto memory (MEMORY.md)Claude's notes to itself from past sessions. The first 200 lines or 25 KB, whichever comes first.Yes — keep only what Claude cannot re-derive.
Environment blockWorking directory, platform, shell, OS, whether this is a git repo. Branch, status, and recent commits load as a separate block.Barely — moving directory changes it.
~/.claude/CLAUDE.mdYour global preferences. Applies to every project.Yes — trim it globally, or move detail into skills.
Project CLAUDE.mdProject conventions and build commands. Read once at session start.Yes — this is the file to keep under 200 lines.
Rule listingThe names of unscoped rules. Path-scoped rules wait.Yes — give rules paths: so they load on file match, not at startup.
Skill descriptionsOne line per skill, so Claude knows what exists. Full bodies do not load here.Yes — fewer skills, shorter descriptions, or disable-model-invocation: true.
MCP tool namesNames only. Full schemas are deferred and fetched on demand by tool search.Partly — names are cheap; schemas are not.

What loads on demand

BlockTriggerWhy it is the big one
File readsClaude reads a file.Thousands of tokens each, and the read stays in the window for the rest of the session.
Path-scoped rulesClaude reads a file matching the rule's paths: pattern.You only pay for rules in the directories you actually touch.
MCP schemasTool search decides a tool is needed.A schema is far larger than the tool's name.
Skill bodiesYou or Claude invoke the skill.The whole SKILL.md, kept across turns.
Hook outputA hook returns additionalContext.Only JSON additionalContext enters the window; plain stdout on exit 0 goes to the debug log only.

The counts /context prints are illustrative of shape, not of your exact numbers — they move with your files, your skill count, and your servers. What does not move is the split: a standing charge you pay every session, and a cost you pay when you use something.

The reframe: everything at startup is a standing charge you pay every

session before you type — so the only question worth asking about any of it is

whether it needs to be there at all, or can load when it is actually used.

Verified against the context window page and the skills page on 2026-10-15. Actual token counts, the 200-line / 25 KB auto-memory cap, and the deferred-schema default all drift with releases; the two-wave shape does not.

Build It

You need one real project where you have actually worked. Do not use a scratch repo — the point is to see your standing charges.

  1. Start a session in the project and run /context. Copy the block names and their token counts into a table.

✅ You pass when you can name the largest startup block without scrolling.

  1. Find the biggest block you control. It is usually the project CLAUDE.md. Count its lines:

``bash wc -l CLAUDE.md ``

  1. Move one section out of it. Pick by shape, not by size:
    • A procedure — a sequence of steps — becomes a skill (Lesson 87).
    • Something true only under one directory becomes a path-scoped rule with a paths: pattern.
    • Something the code already says becomes nothing — delete it.
  1. Start a fresh session and run /context again. The startup number should be smaller by roughly the size of what you moved.
  1. For one real task you run often, count the file reads it always does. That is your per-turn cost, and it is the number that matters more than startup.

Use It

Command / conceptWhen you reach for it
/contextFirst command in any session where you suspect the window is crowded.
wc -l CLAUDE.mdBefore you decide a memory file is "basically small".
paths: on a ruleWhen a rule only matters in one kind of directory.
A skill instead of a memory lineWhen the content is a procedure, not a fact.
A subagent for a research readWhen a task would read many files you will not reuse (Lesson 72).
/compact at a task breakWhen the work is done and the reads behind it are dead weight (Lesson 30).

Exercises

  1. Inventory your startup. In a project you have used for weeks, run /context and write down every auto-loaded block with its cost. Mark each one removable, shrinkable, or fixed. ✅ You pass when your table has at least six rows and exactly one block marked fixed (the system prompt).
  1. Move a block and measure. Take the largest shrinkable block, relocate it (skill, path rule, or delete), restart, and capture /context again. ✅ You pass when the second capture shows a smaller startup total and you can name the block that shrank.
  1. Predict, then verify, the dominant read. Before running a task you know well, write down which file reads you expect Claude to make. Run it. Compare. ✅ You pass when you correctly named the single most expensive read, or can explain precisely which extra read you missed and why the task caused it.

Key Terms

TermWhat people sayWhat it actually means
/context"the token counter"The view of what actually loaded and what it cost — the only honest answer to "why is my window full".
startup context"the preamble"Everything auto-loaded before your first message. You pay it every session whether you use it or not.
deferred MCP schemas"MCP servers cost a fortune"The names load at startup; full schemas load on demand via tool search. The names are cheap. The schemas are not.
skill listing"the skill"Only the skill's name and description load at startup. The body loads when the skill is invoked.
auto memory"it remembers everything"The first 200 lines or 25 KB of MEMORY.md load at startup. Past that, it does not.
standing charge"it's just one line"A cost paid every session. Lines add up across files, skills, and servers faster than anyone expects.

What this lesson skipped

The exact sizes. Model windows, the 200-line / 25 KB memory cap, and deferred-schema defaults are version-gated and change. Read them from /context on your machine, not from a blog post.

Compaction mechanics. What survives when the window fills is Lesson 30.

Cutting without losing capability. This lesson is the diagnosis. The treatment is Lesson 90.

Cache-aware ordering. Context is also a cache. What you put first changes what stays cheap — Lesson 89.

Check yourself

4 questions. Answer before you reveal — recognising the right option is not the same as being able to produce it.

  1. A teammate adds a skill that deploys to production and sets disable-model-invocation: true on it. What does that skill cost you at startup, in a session where you never type its name?

    1. Its full body loads, so Claude knows what the side effect is
    2. Nothing — it is left out of the startup listing entirely and costs zero until invoked
    3. Only its description loads, so Claude can warn you before you trigger it
    4. It loads when Claude reads a file matching its paths: pattern
    Show answer

    B. Nothing — it is left out of the startup listing entirely and costs zero until invoked

    disable-model-invocation: true removes the skill from the startup listing, so neither description nor body is in the window until you invoke it by name. Option A is backwards: the switch exists precisely to keep side-effecting skills out of context. Option C describes the default behavior (description only), which is the thing the switch turns off. Option D confuses a skill with a path-scoped rule; paths: governs automatic activation, not listing cost.

  2. You connect an MCP server that exposes forty tools. You brace for a huge jump in your startup context, but /context barely moves. What is the most likely explanation?

    1. MCP servers never enter the context window
    2. Only the tool names load at startup; the full schemas are deferred and fetched on demand by tool search
    3. The server failed to connect, so nothing loaded
    4. All forty schemas loaded, but /context rounds numbers below 1,000 tokens
    Show answer

    B. Only the tool names load at startup; the full schemas are deferred and fetched on demand by tool search

    By default, MCP tool names are listed at startup so Claude knows what exists, while the much larger schemas are deferred and loaded on demand via tool search. Option A is too strong: names and, when a tool is used, its schema do enter the window. Option C is a symptom you would see as tools failing to appear, not as a quietly small context. Option D misreads /context, which shows the block cost; forty schemas would be a visible jump, not a rounding artifact.

  3. Your project has a rule at .claude/rules/api-conventions.md with paths: src/api/**. You start a fresh session and edit only src/lib/util.ts. What did that rule cost?

    1. A standing charge, because all rules load at startup
    2. Nothing — path-scoped rules load only when a matching file is read
    3. Its full text, because rules are always loaded and never path-scoped
    4. Only its name, because the listing loads every rule's filename
    Show answer

    B. Nothing — path-scoped rules load only when a matching file is read

    A path-scoped rule loads when a file matching its paths: pattern is read, so a session that never touches src/api/ never pays for it. Option A is the classic misconception this lesson exists to kill. Option C contradicts the paths: field, which is exactly what scopes it. Option D is close but wrong: the detail that loads is the rule's content on a match, not a name at startup — that is the difference between a rule and a skill listing.

  4. Your auto-memory file has grown to 900 lines of notes. Which part can you count on being in the window at a new session's start?

    1. All 900 lines, because auto memory always loads in full
    2. None of it, because auto memory is only read on demand
    3. The first 200 lines or 25 KB, whichever comes first
    4. Only the lines Claude wrote most recently, up to 200
    Show answer

    C. The first 200 lines or 25 KB, whichever comes first

    Auto memory loads at startup, but only the first 200 lines or 25 KB, whichever comes first. Option A is the trap: it feels like memory should be all-or-nothing, but it is capped. Option B is wrong in the other direction — it is a startup block, not an on-demand read. Option D invents a recency rule; the cap is positional (the start of the file), which is why what you put at the top matters.
