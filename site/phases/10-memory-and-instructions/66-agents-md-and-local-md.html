LEARN · PHASE 10 · LESSON 66

AGENTS.md, CLAUDE.local.md

You can keep one instruction file for every coding agent you use, and one private file that never gets committed — without loading the wrong one twice.

Type
Learn
Prerequisites
Lesson 65, CLAUDE.md — the 200-Line Rule
Time
~30 minutes

Learning Objectives

  • Predict whether Claude reads your AGENTS.md or your CLAUDE.md, from what is in the repo
  • Keep a CLAUDE.local.md out of git, and share the same personal notes across worktrees
  • Change which instruction files load with the Project instructions setting
  • Choose between an @AGENTS.md import and a symlink, and say why Windows changes the answer
  • Explain what a CLAUDE.local.md does to a repo that relies on AGENTS.md

The Problem

You set up AGENTS.md for the other coding agents you use. You set up CLAUDE.md for Claude Code. Now the same conventions live in two files, and one of them is quietly being ignored.

Or the opposite problem: you keep personal notes — your sandbox URL, your test login — in a CLAUDE.local.md at the project root. You commit it by accident. Your sandbox URL is now in the team's repository, and the next person to open the file is confused about whose URL it is.

Both failures come from the same misunderstanding: which file loads is not a matter of preference. It is decided by what is present in the repo.

The Concept

Claude Code can read a repository's AGENTS.md as its project instructions, so a repo already set up for other agents works without adding a CLAUDE.md. But it does not read both by default. It picks, based on what it finds:

The full default rule, from the docs:

Your repository hasClaude reads
An AGENTS.md, and no CLAUDE.md or CLAUDE.local.md in the working directory or above itYour AGENTS.md
An AGENTS.md and a CLAUDE.md or CLAUDE.local.md in the working directory or above itYour CLAUDE.md files only
A CLAUDE.md that imports AGENTS.md with @AGENTS.mdYour CLAUDE.md, with AGENTS.md included through the import

Read the middle row twice. A CLAUDE.local.md counts as a CLAUDE.md for this check. Adding one to keep your own uncommitted notes in an AGENTS.md repo silently stops Claude from reading AGENTS.md at all. That is the trap this lesson exists for.

You can change the default with the Project instructions setting — open /config and pick one:

ValueWhat Claude reads
claude-md-or-agents-mdCLAUDE.md, or AGENTS.md when no CLAUDE.md/CLAUDE.local.md is present. The default
claude-md-and-agents-mdBoth, each directory's CLAUDE.md first, then its AGENTS.md
claude-mdCLAUDE.md files only
managed-onlyOnly the organization's managed CLAUDE.md and auto memory

Two footnotes. AGENTS.local.md, AGENTS.override.md, and anything under a .agents/ directory are never read. And a CLAUDE.local.md in a worktree — a second checkout of the same repo — is gitignored, so it exists only in the worktree where you made it.

The reframe: AGENTS.md and CLAUDE.md are not two names for one thing you keep in sync — Claude reads whichever the repo's file inventory selects, and the presence of a CLAUDE.local.md silently flips the switch.

CLAUDE.local.md

CLAUDE.local.md is personal, project-specific, and loaded exactly like CLAUDE.md: same parsing, same position in the order, appended after CLAUDE.md in each directory. The only difference is that you are expected to gitignore it. With CLAUDE_CODE_NEW_INIT=1 set, /init and choosing the personal option adds it to .gitignore for you.

Keeping one file for every tool

If you want a single file that all your agents share, keep AGENTS.md and put @AGENTS.md at the top of a CLAUDE.md next to it. Claude reads the import first, then any Claude-specific lines you add below it.

A symlink — ln -s AGENTS.md CLAUDE.md — also works, but check two things first:

  • Editing: Claude reads CLAUDE.md through the link, but the Edit and Write tools refuse to write through a symlink and will redirect to AGENTS.md.
  • Windows: if anyone on the team uses Windows, use the import instead. Creating a symlink needs Administrator or Developer Mode, and Git checks a committed symlink out as a plain text file unless core.symlinks is enabled — leaving that clone with a one-line CLAUDE.md.

Where the two differ

An AGENTS.md read through the Project instructions setting behaves differently from a CLAUDE.md in two places worth remembering: InstructionsLoaded hooks fire for CLAUDE.md but not for a directly-read AGENTS.md (they still fire for an imported one), and an @path import inside AGENTS.md that reaches outside your working directory loads without the approval prompt once you have approved external imports for the project.

Direct AGENTS.md reading requires Claude Code v2.1.277 or later, and some sessions — notably some on Amazon Bedrock, or with telemetry disabled, before v2.1.281 — read CLAUDE.md only (checked October 2026).

Build It

  1. In a repo you work in, list the instruction files: ls CLAUDE.md AGENTS.md CLAUDE.local.md (some will be absent). Using the table above, write down which one Claude reads by default.

✅ You pass when you can name the file that loads and the one that is ignored, and why.

  1. If you have an AGENTS.md and want Claude to read it, either remove the stray CLAUDE.md/CLAUDE.local.md or set Project instructions to claude-md-and-agents-md in /config.

✅ You pass when a fresh session's /context shows the file you intended under Memory files.

  1. Create a CLAUDE.local.md with one personal preference. Add it to .gitignore. Run git status.

✅ You pass when git status does not list the file, and a fresh session still loads its content.

  1. Now that CLAUDE.local.md exists, re-check the AGENTS.md case from step 1. Run /context.

✅ You pass when you can explain why the AGENTS.md stopped loading even though you changed nothing about it.

  1. If your project keeps AGENTS.md for other tools, add @AGENTS.md at the top of CLAUDE.md and confirm the content appears once.

✅ You pass when /context shows CLAUDE.md under Memory files and you can say the AGENTS.md content is there through the import, not twice.

Use It

Command / conceptWhen you reach for it
AGENTS.mdOne instruction file shared with other coding agents
CLAUDE.mdInstructions for Claude Code specifically
CLAUDE.local.mdYour personal, project-specific, gitignored notes
/config → Project instructionsChoose which files load, and whether both do

ln -s AGENTS.md CLAUDE.mdSymlink alternative — skip it on Windows

Exercises

  1. You have a repo with both AGENTS.md and CLAUDE.md, and you want Claude to read both without merging them by hand. Change the setting, start a fresh session, and prove the order with /context. ✅ You pass when both files are listed and you can state which directory's CLAUDE.md is read before its AGENTS.md.
  1. A teammate clones your repo on Windows and their CLAUDE.md is one line pointing at AGENTS.md instead of the instructions. Diagnose what happened and fix it so it works on their machine. ✅ You pass when you can name the cause (a committed symlink checked out as text) and the fix (an @AGENTS.md import).
  1. You want your personal notes in an AGENTS.md repo without losing AGENTS.md. Set it up, then verify with /context. ✅ You pass when both your CLAUDE.local.md content and your AGENTS.md content are loaded, and you can say which setting made that possible.

Key Terms

TermWhat people sayWhat it actually means
AGENTS.md"the file for other agents"A shared instruction file Claude Code can read as project instructions — but only when no CLAUDE.md/CLAUDE.local.md is present, unless you change the setting.
Project instructions"which file wins"The /config setting that decides whether Claude reads CLAUDE.md, AGENTS.md, both, or managed instructions only.
CLAUDE.local.md"just a private CLAUDE.md"Loaded exactly like CLAUDE.md — and counted as one, so it suppresses AGENTS.md.
symlink vs import"the same thing"A symlink is a link the tools may refuse to write through and Windows may not check out; an import copies the content in at launch.
.agents/ directory"another place for agents"Not read. Neither is AGENTS.local.md or AGENTS.override.md.
worktree"another checkout"A second working copy of the same repo. A gitignored CLAUDE.local.md exists only in the one where you made it.

Check yourself

4 questions. Answer before you reveal — recognising the right option is not the same as being able to produce it.

  1. A repo has an AGENTS.md with all the conventions, and no CLAUDE.md. A teammate adds a CLAUDE.local.md to keep their own notes. What happens to AGENTS.md?

    1. Nothing — CLAUDE.local.md is personal and ignored for loading decisions
    2. Claude stops reading AGENTS.md, because CLAUDE.local.md counts as a CLAUDE.md
    3. Claude reads both, with CLAUDE.local.md last
    4. Claude reads neither, because the files conflict
    Show answer

    B. Claude stops reading AGENTS.md, because CLAUDE.local.md counts as a CLAUDE.md

    The presence check treats CLAUDE.local.md as a CLAUDE.md, so adding one suppresses AGENTS.md by default. Option 0 is the tempting wrong answer because 'local' sounds excluded from decisions — but it counts, which is exactly the trap.

  2. You want Claude to read both your CLAUDE.md and your AGENTS.md, in each directory, without merging them yourself. What do you change?

    1. Add @AGENTS.md to CLAUDE.md and delete AGENTS.md
    2. Set Project instructions to claude-md-and-agents-md in /config
    3. Rename AGENTS.md to AGENTS.local.md
    4. Nothing — Claude reads both by default
    Show answer

    B. Set Project instructions to claude-md-and-agents-md in /config

    The Project instructions setting selects claude-md-and-agents-md, which reads each directory's CLAUDE.md first and its AGENTS.md after. Option 0 is tempting because the import works, but it makes AGENTS.md load through CLAUDE.md, which is the opposite of reading both as separate files.

  3. A teammate on Windows clones your repo. Their CLAUDE.md is one line that points at AGENTS.md instead of holding the instructions. What most likely happened?

    1. The CLAUDE.md was committed as a symlink, and Git checked it out as a plain text file
    2. Claude Code stripped the file because it conflicted with AGENTS.md
    3. CLAUDE.local.md was missing on their machine
    4. Their version of Claude Code is too old to read AGENTS.md
    Show answer

    A. The CLAUDE.md was committed as a symlink, and Git checked it out as a plain text file

    A committed symlink needs Developer Mode or Admin on Windows, and Git checks it out as text unless core.symlinks is enabled, leaving a one-line file. Option 3 is tempting because AGENTS.md support is version-gated — but the symptom is a truncated CLAUDE.md, which points at the symlink, not the version.

  4. You keep personal test credentials in CLAUDE.local.md and work across two worktrees of the same repo. You open the second worktree and the file is gone. Why?

    1. Claude deleted it because it was gitignored
    2. A gitignored CLAUDE.local.md exists only in the worktree where you created it
    3. CLAUDE.local.md only loads in the repository root, not in worktrees
    4. You need to set Project instructions to claude-md first
    Show answer

    B. A gitignored CLAUDE.local.md exists only in the worktree where you created it

    Because it is gitignored, the file is not carried into a new checkout, so each worktree needs its own. Option 2 is tempting because 'root only' sounds like a loading rule — but the real cause is that the file was never copied, not that loading is scoped.
